# VFS/CLI Parity Ledger

Date: 2026-06-28
Inspected Bloom commit: `c14e928ec8c7697c0baac30d8da89ed3214ffbb8`

This ledger classifies user-facing workflows across the `bloom` CLI and VFS.
Statuses:

- `parity`: both surfaces complete the workflow end-to-end with equivalent gates.
- `cli_only`: only the CLI intentionally supports it today.
- `vfs_only`: only the VFS intentionally supports it today.
- `hybrid_required`: current product flow intentionally combines VFS staging/review with CLI or foreground VFS execution.
- `gap`: product direction needs parity, but one side is missing or unsafe.

Benchmark tracks:

- `track_a`: eligible for equal-capability CLI-vs-VFS benchmark.
- `track_b`: eligible only for current-product recommendation benchmark.
- `track_c`: implement before parity benchmarking.
- `exclude`: unsafe, live-only, flaky, or not agent-relevant for parity yet.
