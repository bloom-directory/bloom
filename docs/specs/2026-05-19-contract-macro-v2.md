# 2026-05-19 — `contract!` v2: storage, events, reentrancy in the language

## Motivation

The `bloom_chain_abi::contract!` macro currently owns selectors and calldata
parsing. Everything else a contract author needs — storage layout, event
encoding, reentrancy guards — is still hand-rolled. The DEX example makes the
gap visible:

- **Storage keys.** `bloom-dex-pair` declares 11 typed slots through ~50 lines
  of `fn k_*()` helpers that concatenate domain tags and call `blake3`. Every
  petal repeats the pattern. Typed accessors (`read_u256` / `write_u128` /
  `read_addr` / `read_bool` …) are re-written per crate.
- **Events.** `bloom-dex-abi/src/events.rs` exposes seven `pack_*` functions
  whose only job is `Vec::extend_from_slice` over the same fixed-width rules
  the macro already uses for calldata. Topic constants are generated by a
  `build.rs`. The contract author still calls `log::emit(&[TOPIC], &data)`
  with the right pair of arguments.
- **Reentrancy.** `bloom-dex-reentrancy` is an *entire separate petal* whose
  sole job is to acquire/release a lock slot in the pair, in lieu of a
  language-level modifier. The pair exposes `_mint_inner`, `_burn_inner`,
  `_swap_inner`, `lock_check_and_set`, `lock_clear` as `#[internal]` methods
  gated on the orchestrator's address. The orchestrator's own header file
  says "v1 will add `host.try_call` for a finally-clause pattern" — i.e. the
  design was already understood to be a workaround.
- **Module scope.** `bloom-dex-wloom` is a wrapped-native-asset primitive
  (the analogue of WETH) with no AMM logic. It does not belong under
  `examples/dex/crates/`.

`bloom-dex-abi` was created in the prior ABI-ownership refactor as a thin
DEX-wide shim. With the changes below it loses every responsibility it has
and is deleted.

## Goals

1. **Single-source ABI**: the `contract!` macro is the only place where on-
   wire encoding (calldata, return data, event logs) and storage layout are
   defined. Hand-rolled `blake3(b"…")` calls and hand-packed log payloads
   disappear from contract source.
2. **Solidity-grade ergonomics**: declaring a storage variable, an event,
   or a non-reentrant function is a single line of DSL.
3. **No regressions in correctness**: every contract that compiles today
   has a 1:1 migration that produces byte-identical calldata, return data,
   event logs, and selectors (selector parity is non-negotiable).
4. **WLOOM out of DEX**: `bloom-dex-wloom` moves to `examples/wloom/` and
   stops being a DEX crate.
5. **Delete `bloom-dex-abi`**: zero remaining call sites after migration;
   selector parity becomes a self-test in `bloom-chain-abi-macros`.

## Non-goals

- New on-wire formats. Existing calldata, return data, event topics, and
  storage-key derivation rules are preserved bit-for-bit.
- A general storage compiler (no slot packing, no struct-flattening
  optimisations). Each declared variable lives in one 32-byte slot or one
  mapping namespace, period.
- Async-aware reentrancy semantics (out of scope for v0; the petal VM
  unwinds synchronously).
- Cross-petal storage sharing (we keep the ability to opt-out per-field,
  but the macro does not introduce a new sharing primitive).

## Design

### A. Storage declarations

A new `storage { … }` block inside `contract!`:

```rust
contract! {
    contract Pair {
        storage {
            // Scalar slots — auto-namespaced to `pair.<field>`.
            token0:     Address;
            token1:     Address;
            reserve0:   u128;
            reserve1:   u128;
            k_last:     U256;
            lock:       bool;
            reentrancy: Address;
            self_addr:  Address;

            // Mappings — slot key = blake3("pair.balances:" || key_bytes).
            balances:    Mapping<Address, U256> @ "erc20.balance:";
            allowances:  Mapping<(Address, Address), U256> @ "erc20.allowance:";

            // Cross-petal-shared scalar (LP token total supply, shared with
            // bloom-dex-erc20). Explicit domain overrides the auto namespace.
            total_supply: U256 @ "erc20.total_supply";
        }

        init(token0: Address, token1: Address, reentrancy: Address, self_addr: Address);
        fn token0() -> Address;
        fn mint(to: Address);
        // …
    }
}
```

**Naming.** Default slot tag for `field` inside `contract Pair` is
`"pair.field"`. Override with `@ "explicit.tag"`. The override is the
*only* way to share a slot between contracts and is intended exclusively
for the ERC-20-mixin case currently shared between pair and bloom-dex-erc20.

**Generated surface.** For scalar `field: T`, the macro emits a `storage`
module with `pub fn field() -> T` and `pub fn set_field(v: T)`. For
`Mapping<K, V>`, it emits a nested module `storage::field` with `pub fn
get(k: &K) -> V` and `pub fn set(k: &K, v: V)`. Slot bytes are derived as:

- Scalar: `blake3("<auto-or-explicit-tag>")[..32]`.
- Mapping: `blake3("<tag>" || encode_key(k))[..32]`, where `encode_key`
  reuses the calldata encoder (Address=32B, U256=32B, u128/u64 left-padded
  to 32B, tuple = concat).

**Default values.** Reads of unwritten slots return the zero value for the
type (`0`, `false`, all-zero address, `U256::ZERO`). Matches the current
hand-rolled behaviour and Solidity semantics.

**Supported types (v0).** `Address`, `U256`, `u128`, `u64`, `bool`,
`[u8; 32]`, and `Mapping<K, V>` where `K ∈ {Address, U256, (Address,
Address), (Address, U256)}` and `V` is any supported scalar. `bytes` /
dynamic strings are deferred to v1.

**Reserved tags.** Tags prefixed with `__macro.` are reserved for
macro-managed slots (e.g. the reentrancy lock — see §C). Hand-written
`@ "..."` overrides cannot start with that prefix.

### B. Events

Declared inside `contract!`:

```rust
event Transfer(#[indexed] from: Address, #[indexed] to: Address, value: U256);
event Approval(#[indexed] owner: Address, #[indexed] spender: Address, value: U256);
event Mint(#[indexed] sender: Address, amount0: U256, amount1: U256);
event Burn(
    #[indexed] sender: Address,
    amount0: U256,
    amount1: U256,
    #[indexed] to: Address,
);
event Swap(
    #[indexed] sender: Address,
    a0_in: U256, a1_in: U256, a0_out: U256, a1_out: U256,
    #[indexed] to: Address,
);
event Sync(reserve0: u128, reserve1: u128);
event PairCreated(
    #[indexed] token0: Address,
    #[indexed] token1: Address,
    pair: Address,
    index: u64,
);
```

**Topic.** First (and currently only) topic is `blake3(canonical_sig)[..4]`
where `canonical_sig = "Name(t1,t2,…)"` with the same lowercase type-name
table as method signatures (`address`, `u256`, `u128`, `u64`, `bool`,
`bytes`).

**Indexed-vs-data encoding (v0).** `bloom_petal_sdk::log::emit` accepts
only 4-byte topics today, so the macro encodes `#[indexed]` fields as
32-byte chunks **prepended to the data blob** in declaration order, with
non-indexed fields concatenated after. This matches the existing DEX
`pack_*` wire format byte-for-byte and is the migration path
`bloom-dex-abi::events::pack_*` callers see. A later spec can extend the
host import to accept a separate `&[[u8; 32]]` topics slice without
breaking the macro's caller-facing API (`emit_transfer(from, to, value)`).

**Generated surface.** For each event, the macro emits a `pub fn
emit_<snake_name>(...)` taking each field by reference, in declaration
order, with no separate "topic vs data" split visible to the caller. It
calls `log::emit(&topics, &data)` under the hood.

**Compatibility.** Today's `bloom-dex-abi::events` topics are generated
by a `build.rs` from a fixed table that already uses the
`blake3(sig)[..4]` rule. The macro-generated topics are byte-identical
provided the canonical signatures match the existing table. The migration
PR must include a parity assertion that compares every old constant to
the new macro-derived value before the old constants are deleted.

### C. Reentrancy guard

A function-level attribute on `fn` declarations inside `contract!`:

```rust
contract! {
    contract Pair {
        // …storage, events…

        #[nonreentrant]
        fn mint(to: Address);

        #[nonreentrant]
        fn burn(to: Address);

        #[nonreentrant]
        fn swap(amount0_out: U256, amount1_out: U256, to: Address);
    }
}
```

**Semantics.** Contract-wide lock (a single auto-managed slot, tag
`"__macro.nonreentrant.<contract_snake>"`). The macro wraps the dispatched
function with:

```text
if state::read(LOCK) == [..., 0x01]: revert "<contract>: reentrant call"
state::write(LOCK, [..., 0x01])
let ret = <user body>
state::write(LOCK, [..., 0x00])  // on the success path only — see below
return ret
```

The lock is **not** cleared on revert. The transaction is atomic at the
chain level: a revert rolls the lock write back along with everything
else. This matches the current cross-petal guard's revert behaviour and
removes the need for `try_call` / `host.try_call` for the v0 cut.

**Divergent return contract.** The post-handler clear is only reachable
on the success path *if the handler returns normally*. Petal SDK
terminators (`petal::return_data`, `petal::revert`) are divergent
(`-> !`) — they end wasm guest execution without ever returning to the
macro dispatcher. For success-path divergent returns the macro therefore
also emits a helper inside the contract's `abi` module:

```rust
pub fn nonreentrant_lock_clear() { /* writes zeros to the lock slot */ }
```

User handlers that diverge on the success path **must** call
`<contract>::abi::nonreentrant_lock_clear()` immediately before
`petal::return_data(...)`. Revert paths require no explicit clear
(transaction rollback handles them).

**Effects on the DEX.**

- `bloom-dex-reentrancy` crate is **deleted**.
- The pair's `_mint_inner` / `_burn_inner` / `_swap_inner` /
  `lock_check_and_set` / `lock_clear` `#[internal]` methods are deleted;
  the public `mint` / `burn` / `swap` methods are simply marked
  `#[nonreentrant]`.
- The factory and router stop wiring `reentrancy_addr` through. The
  pair's `init` calldata shrinks from 128 → 96 bytes (drop the
  `reentrancy_addr` field). The router's pair-deploy path drops one
  argument.

**Compatibility note.** This is a wire-format break in the pair's `init`
calldata. Acceptable because v0 ships these contracts together and there
are no deployed pairs. The migration PR updates the pair, factory,
router, DEX integration tests, and the DEX spec in one go.

### D. WLOOM extraction

`bloom-dex-wloom` moves to a new top-level example crate at
`examples/wloom/` with its own `Cargo.toml` and tests. The DEX router /
integration tests that need a wrapped-native token import it via path
dep. The DEX spec stops mentioning WLOOM as a DEX module and instead
references it as an external dependency.

Rationale: wrapped-native is a primitive; it belongs alongside other
canonical example contracts, not under the AMM. This change is purely a
reorganisation — no logic changes.

### E. `bloom-dex-abi` deletion

Every responsibility migrates:

| Today                                             | After |
|---------------------------------------------------|-------|
| `bloom-dex-abi::selectors::*` constants           | Each petal exports its own via the macro's `pub mod abi` |
| `bloom-dex-abi::events::*_EVENT` topic constants  | Each petal exports its own via the macro's `pub mod abi::events` |
| `bloom-dex-abi::events::pack_*`                   | Deleted (callers use macro-generated `emit_*`) |
| `bloom-dex-abi::encode`, `::decode`, `::u256`     | Already thin re-exports of `bloom-chain-abi`; callers switch to direct imports |
| `assert_selector_parity!` macro                   | Becomes a `bloom-chain-abi-macros` self-test |

After migration, `examples/dex/crates/bloom-dex-abi/` is `rm -rf`'d and
removed from the workspace.

**Cross-petal selector imports.** Router and factory need pair / ERC-20
selectors. The macro already emits `pub mod abi` inside the petal crate;
this spec just makes it the canonical import path:

```rust
// router crate
use bloom_dex_pair::abi as pair_abi;

let cd = pair_abi::call::mint(to);
petal::call(pair_addr, &cd, value).unwrap();
```

## Macro DSL — full grammar

```text
contract! {
    contract <Name> {
        [storage { <storage-decl>* }]
        [event <EventName>(<event-arg>,*);]*
        [init(<arg>,*);]
        [<fn-decl>]*
    }
}

storage-decl  := <ident> ":" <ty> ["@" <string-lit>] ";"
              |  <ident> ":" "Mapping" "<" <key-ty> "," <val-ty> ">" ["@" <string-lit>] ";"
event-arg     := ["#[indexed]"] <ident> ":" <ty>
fn-decl       := ["#[internal]"] ["#[nonreentrant]"] "fn" <ident> "(" <arg>,* ")" ["->" <ty>] ";"
arg           := <ident> ":" <ty>
```

Combining `#[internal]` and `#[nonreentrant]` on the same function is a
compile error (internal methods cannot be re-entered by external
callers; combining the two is a smell).

`#[indexed]` on `bytes` is a compile error (we never hash dynamic data
into a topic — indexed fields must have a fixed 32-byte representation).

## Semantics — invariants the macro must preserve

1. **Selector parity** (existing): every `fn` selector equals
   `blake3("<contract_snake>.<fn_snake>(<types>)")[..4]`. v2 must not
   regress this; the existing macro-DSL parity tests stay green.
2. **Event topic parity**: `event Name(t1, t2, …)` produces topic =
   `blake3("Name(<types>)")[..4]`. The migration PR adds a one-shot
   assertion against the old `bloom-dex-abi::events` constants.
3. **Slot derivation determinism**: storage slots are a pure function of
   the contract name and field declaration. Two compilers built from the
   same source produce byte-identical slot keys.
4. **Zero-on-unwritten**: reads from never-written slots return the
   type's zero value.
5. **Lock isolation**: `#[nonreentrant]` lock slot tag `"__macro.nonreentrant.<contract_snake>"`
   is reserved; user code cannot collide with it (the `__macro.` prefix
   is rejected from explicit `@` overrides).

## Migration impact

Single PR (no intermediate states):

- `crates/bloom-chain-abi/`
  - `src/event.rs` gains `event_signature_topic(name, &[type_str])`
    helper used by the macro and by tests.
  - `src/storage.rs` (new): the `Mapping` runtime type + slot-key helpers
    invoked by macro-generated code. Encoder rules re-used from
    `src/encode.rs`.
- `crates/bloom-chain-abi-macros/`
  - Extend the DSL parser with `storage { … }`, `event …;`, and the
    `#[nonreentrant]` attribute.
  - Generate `pub mod abi { pub mod call { … } pub mod events { … } }`
    inside each contract crate.
  - New self-test: macro-emitted selectors match `blake3(method_sig)[..4]`
    over a wide fuzz; same for events.
- `examples/dex/crates/bloom-dex-pair/` — declare storage + events
  inside `contract!`; delete `k_*` helpers, `pack_*` callers, and the
  `_inner` / `lock_*` `#[internal]` methods. Public methods get
  `#[nonreentrant]`. Init calldata shrinks to 96 bytes.
- `examples/dex/crates/bloom-dex-factory/`,
  `examples/dex/crates/bloom-dex-router/`,
  `examples/dex/crates/bloom-dex-erc20/` — declare storage + events
  inside `contract!`; replace `bloom_dex_abi::*` imports with direct
  `bloom_chain_abi::*` + sibling petal `::abi::*` imports.
- `examples/dex/crates/bloom-dex-reentrancy/` — **deleted**.
- `examples/dex/crates/bloom-dex-abi/` — **deleted** after callers
  migrate.
- `examples/dex/crates/bloom-dex-wloom/` → `examples/wloom/`. Update
  `Cargo.toml` workspace members; update DEX integration tests that
  import WLOOM.
- DEX spec (`docs/specs/2026-05-18-bloom-dex-design.md`) — update
  §6 (storage), §8 (reentrancy: in-language modifier, no separate
  petal), §10 (events: macro-emitted), and remove the reentrancy-petal
  diagram. Add a one-liner pointing to WLOOM's new home.

## Resolved decisions

1. **`abi` modules live inline** in the same crate that declares
   `contract!` (e.g. `bloom_dex_pair::abi`). Sibling ABI crates are
   deferred until consumer-side guest-bloat becomes a measured problem.
2. **`bytes` storage and event fields are deferred to v1.** The grammar
   reserves space for them (length slot + chunked content slots for
   storage; length-prefixed data blob for events) but the parser
   rejects them with a clear "deferred to v1" diagnostic in v0.
3. **No `Mapping::delete` / `unset` in v0.** Contracts call
   `storage::map::set(&k, V::zero())` and rely on zero-on-read.
   Storage-cost recovery is a v1 concern.
